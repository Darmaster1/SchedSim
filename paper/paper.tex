\section{Introduction}

A CPU scheduler must repeatedly decide which ready process runs next. Classical
policies such as Shortest Job First and Shortest-Remaining-Time-First are
provably strong \emph{if} the scheduler knows each process's remaining burst
length in advance; real schedulers never have this information and instead
rely on static priorities, fixed time slices, or simple estimators
\cite{silberschatz2013}. This paper investigates, through simulation rather
than kernel modification, whether (i) a machine-learning estimate of burst
length can improve priority-based scheduling, and (ii) a Round Robin time
quantum chosen adaptively -- by hand-written rules or by a reinforcement
learning (RL) agent -- outperforms a fixed quantum. A 2017 survey
\cite{dias2017} motivates this question; Section~II treats it as a pointer
into the literature, re-checking its central claims against primary sources
rather than repeating them uncritically.

This paper makes no claim that ML or RL improves scheduling in general. It
tests whether, and under what pilot-scale conditions, these methods help,
treating fairness loss, tail-latency cost, and context-switch overhead as
first-class outcomes. All code is openly available; every table in this paper
is generated directly from that code's output (see \S VI).

\textbf{Contributions.} (1) A single open-source simulator evaluating all six
algorithms under identical workloads and counting conventions; (2) a direct,
statistically tested comparison between performance-oriented and
fairness-protected ML priority ranking; (3) separate accounting of
burst-prediction accuracy versus scheduling outcome; (4) a frozen evaluation
protocol for CWABP against exponential averaging, run end-to-end; and (5) full
transparency about pilot-scale limitations, including two implementation bugs
this project's own test suite caught during development (\S VI-C).

\section{Related Work}

We re-verified the central claims of a 2017 survey \cite{dias2017} against
original sources. Negi and Kishore \cite{negi2005} modified a Linux 2.4 kernel
scheduler and report a 1.4--5.8\% turnaround-time reduction via
decision-tree-learned time-slice classes, attributed to fewer context
switches -- confirmed at the abstract level. Helmy et al.\ \cite{helmy2015}
report strong grid-burst prediction (k-NN best) on the GWA-T-4 trace; the
specific correlation/RAE figures quoted by the survey were not independently
re-verified. Two sources cited only through the
survey (a 2004 Negi \& Kishore paper and a Dolev/Mendelson/Shilman technical
report) could not be located at all.

More recent dynamic-quantum Round Robin work includes DABRR
\cite{dash2016}, an effective-time-slice RR \cite{tajwar2017}, $k$-means-based
RR \cite{mostafa2020}, and an agent-based adaptive RR compared against twelve
baselines \cite{khan2025}. RL has been applied to real scheduler parameters by
Han and Lee \cite{han2020} (Android's Energy-Aware Scheduler) and, in preprint
form, to general adaptive resource scheduling \cite{li2024}. Within a necessarily
limited search, we did not find a peer-reviewed study comparing fixed,
rule-based, and Q-learning Round Robin quantum selection \emph{together} under
shared tie-breaking rules while reporting worst-case waiting and starvation
counts, nor a protected-vs-unprotected ML priority comparison reporting
explicit inversion and starvation statistics -- the gap this study targets.

\section{System Design}

\subsection{Simulator Architecture}
\texttt{schedsim} runs five stages in strict sequence: (1) seeded workload
generation, (2) burst-length prediction fitted on training data and selected
on validation data, (3) discrete-event scheduling restricted to information a
real scheduler could observe, (4) metrics computation from the resulting event
log, and (5) statistical analysis. Round Robin quantum policies (E, F) never
receive true burst lengths or future arrivals -- only queue length,
accumulated waiting time, and \emph{predicted} remaining bursts.

\subsection{Synthetic Workloads}
Each workload is a deterministic function of a specification and an integer
seed; training, validation, and test splits use disjoint seed ranges by
construction. Processes carry four synthetic attributes (named after, but not
drawn from, real Linux process fields) whose correlation with true log-burst
length is a controllable design parameter, ranging from strong ($\rho=0.95$)
to deliberately misleading ($\rho=-0.70$). Ten in-distribution workload
categories (varying burst-length distribution, arrival pattern, priority
assignment, and feature strength) appear in all three splits; three
\emph{shifted} categories -- misleading features, heavy-tailed bursts, and a
120-process queue -- appear only in the test split, to probe generalisation.

\section{Algorithms and Machine Learning Models}

\subsection{Common Definitions}
For process $i$ with arrival $a_i$, first dispatch $s_i$, completion $c_i$,
and true burst $b_i$: turnaround $T_i = c_i - a_i$, waiting $W_i = T_i - b_i$,
response $R_i = s_i - a_i$. A context switch is charged (1.0 time unit in the
main experiments) whenever dispatch switches between two different processes
with no intervening idle interval.

\subsection{The Five Candidate Burst Prediction Models}
A real operating system cannot observe future execution requirements. To bridge this information gap, candidate regression estimators predict the expected CPU burst length $\hat{B}_i$ based strictly on four observable memory management attributes: virtual memory size (\texttt{vsize}), code segment size (\texttt{text}), end of code boundary (\texttt{endcode}), and dynamic library allocation size (\texttt{vmlib}). True burst length, arrival time, and static priority are structurally omitted to prevent target leakage. We evaluate five distinct paradigms:

\begin{enumerate}[leftmargin=*,itemsep=1pt,topsep=2pt]
\item \textbf{Ordinary Least Squares Linear Regression (\texttt{linear}):} Fits a linear hyperplane $\hat{y} = \mathbf{w}^T \mathbf{x} + b$ minimising residual sum of squares. Because inference requires only $\mathcal{O}(d)$ floating point operations, it imposes negligible dispatch overhead inside an OS scheduler.
\item \textbf{$k$-Nearest Neighbors Regressor (\texttt{knn}):} Instance-based non-parametric regression with $k=5$ neighbors. Predictions represent the uniform average of the $k$ closest historical processes in standardized Euclidean feature space. While effective in small-scale trace studies, neighbor search incurs $\mathcal{O}(N \cdot d)$ complexity per dispatch.
\item \textbf{Classification and Regression Trees (\texttt{tree}):} A CART decision tree constrained to $\mathrm{max\_depth}=6$. It recursively partitions the feature space along orthogonal hyperplanes minimising mean squared error, yielding explicit if-else rules readily implementable in kernel C code.
\item \textbf{Random Forest Regressor (\texttt{random\_forest}):} An ensemble of 100 decorrelated decision trees ($\mathrm{max\_depth}=8$) trained on bootstrap subsets of the training workloads. Ensembling mitigates high-variance outlier predictions at the expense of $100\times$ higher inference latency.
\item \textbf{Support Vector Regressor (\texttt{svr}):} Radial basis function (RBF) kernel SVR ($C=10.0, \epsilon=0.5$). It maps features into an infinite-dimensional RKHS, fitting a flat margin tube that ignores deviations under $\epsilon$.
\end{enumerate}

\subsection{Priority Family (A, B, C)}
\textbf{A} dispatches the ready process with the smallest priority number
(FCFS/ID tie-break), running to completion. \textbf{B} blends min-max
normalised priority $\hat P_i$ and predicted burst $\hat B_i$ into
$\mathrm{Score}_i = \alpha \hat P_i + (1-\alpha)\hat B_i$, dispatching the
lowest score; $\alpha{=}1$ reproduces A exactly (verified by unit test; \S
VI-B). \textbf{C} adds two safeguards on top of B's score: a
\emph{maximum-wait override} that, once any ready process has waited $\geq
W_{\max}$, dispatches the earliest-arrived overdue process regardless of
score; and \emph{bounded inversion}, restricting dispatch to processes within
priority gap $G$ of the best ready priority otherwise. Critically, \textbf{the
override does not guarantee any process waits at most $W_{\max}$} -- an
overdue process must still wait for the currently running process and any
earlier-arrived overdue peers -- so starvation-threshold violations (wait
$>100$) are measured, not assumed away. $(W_{\max}, G)$ are selected on
validation data to minimise mean max-waiting subject to mean average waiting
$\leq 1.10\times$ Algorithm B's; when no grid point satisfies this (observed
at this pilot's tuned $\alpha{=}0$, where B is already near-SJF-optimal), the
feasible-closest point is used instead of an unvalidated default -- a concrete
answer to a question the original protocol specification left open.

\begin{algorithm}[h]
\small
\caption{Algorithm C: Protected ML Priority Scheduling}
\label{alg:c}
\KwIn{Ready set $R(t)$; priorities $p_i$; predicted bursts $\tilde b_i$; waits $w_i$; threshold $W_{\max}$; gap $G$}
\KwOut{Process $i^\star$ to dispatch at time $t$}
$O \gets \{\,i \in R(t) : w_i \geq W_{\max}\,\}$\;
\eIf{$O \neq \emptyset$}{
  $i^\star \gets \arg\min_{i \in O} (\mathrm{arrival}_i,\ i)$ \tcp*{max-wait override}
}{
  $p^\star \gets \min_{i \in R(t)} p_i$\;
  $E \gets \{\,i \in R(t) : p_i - p^\star \leq G\,\}$ \tcp*{bounded inversion}
  $i^\star \gets \arg\min_{i \in E} \mathrm{Score}_i$ \tcp*{Score as in Alg. B}
}
\Return $i^\star$\;
\end{algorithm}

Algorithm~\ref{alg:c} summarises the dispatch rule; note that the override
branch (lines 2--3) is checked \emph{before}, and takes precedence over, the
bounded-inversion branch, which is precisely why it can cross the priority-gap
boundary $G$ when a process is overdue.

\subsection{Round Robin Family (D, E, F)}
\textbf{D} is FIFO Round Robin with constant quantum $q$, selected on
validation data from candidate set $\mathcal{Q} = \{2,4,8,16\}$. \textbf{E} chooses among the same four
quanta using hand-written thresholds on queue length, median predicted
remaining burst, and the dispatched process's accumulated wait -- shrinking
the quantum under heavy predicted load, growing it for a long-waiting
process. \textbf{F} replaces E's hand-written rule with a tabular Q-learning
agent (Watkins' update, \S IV-E) trained offline and evaluated with a frozen,
exploration-off policy, so that by evaluation time F behaves as a fixed
policy exactly like D and E -- just one \emph{produced} by training rather
than hand-specified.

\subsection{Q-Learning Formulation (Algorithm F)}
To dynamically match the time quantum to instantaneous workload characteristics, Algorithm~F models quantum selection as an episodic Markov Decision Process:
\begin{itemize}[leftmargin=*,itemsep=1pt,topsep=2pt]
\item \textbf{State Space $\mathcal{S}$ ($|\mathcal{S}|=144$):} Defined by a Cartesian combination of four binned continuous observations: (1) ready queue length $|R(t)| \in \{[1,4), [4,9), [9,\infty)\}$; (2) mean predicted remaining burst $\bar{b}_{\text{rem}} \in \{[0,4), [4,12), [12,30), [30,\infty)\}$; (3) maximum queued waiting time $W_{\text{queued}} \in \{[0,25), [25,100), [100,\infty)\}$; and (4) load imbalance metric $I = \max(b) / \bar{b} \in \{[0,1.5), [1.5,3.0), [3.0,\infty)\}$. This yields $4 \times 4 \times 3 \times 3 = 144$ discrete states.
\item \textbf{Action Space $\mathcal{A}$:} Index $a \in \{0,1,2,3\}$ choosing $q \in \mathcal{Q} = \{2, 4, 8, 16\}$ time units.
\item \textbf{Reward Function $r(s,a)$:} Penalizes the marginal increase in total queue waiting time between consecutive dispatch events, augmented with regularization terms for response latency and tail starvation:
\begin{equation}
r = - \Delta W_{\text{total}} - 0.1 \Delta R_{\text{mean}} - 0.2 \Delta W_{\text{tail}}
\end{equation}
\item \textbf{Update Rule:} Watkins' tabular Q-learning:
\begin{equation}
Q(s,a) \leftarrow Q(s,a) + \eta \left[ r + \gamma \max_{a' \in \mathcal{A}} Q(s',a') - Q(s,a) \right]
\end{equation}
with learning rate $\eta=0.15$ and discount factor $\gamma=0.90$. Training applies an $\varepsilon$-greedy exploration schedule decaying from $\varepsilon_0=1.0$ to $\varepsilon_{\text{end}}=0.05$. At evaluation, policy $\pi(s) = \arg\max_a Q(s,a)$ is strictly frozen with ties broken in favor of the smaller quantum.
\end{itemize}

\section{The CWABP Extension}
Exponential averaging, $\hat\tau_n = \beta \tau_n + (1-\beta)\hat\tau_{n-1}$,
is the textbook SRTF/SJF burst estimator ($\beta=0.5$) but adapts only slowly after a
behaviour change and ignores any signal observable \emph{before} a burst
begins. We propose the Correlation-Weighted Adaptive Burst Predictor (CWABP): given an observable per-burst scalar $x$ (e.g.\
preceding I/O size), maintain a sliding window of the last $K=8$ pairs $(x_j, \ln \tau_j)$ per
process. If the sample correlation $r$ in the window is non-zero, a log-linear regression is computed:
\begin{equation}
\ln \hat{\tau}_{\text{reg}} = \text{slope} \cdot x + \text{intercept}
\end{equation}
The final burst estimate blends the regression prediction with the exponential averaging baseline, weighted by shrunk squared correlation $\lambda r^2$ ($\lambda=0.5$):
\begin{equation}
\hat{\tau}_{\text{CWABP}} = \exp\left( \lambda r^2 \ln \hat{\tau}_{\text{reg}} + (1 - \lambda r^2) \ln \hat{\tau}_{\text{EA}} \right)
\end{equation}
With an uninformative feature, the sample correlation over a small window is not reliably zero
($\mathrm{sd}(r)\approx 1/\sqrt{K-3}$), risking spurious extrapolation; we bound this through two explicit structural safeguards:
\begin{enumerate}[leftmargin=*,itemsep=1pt,topsep=2pt]
\item \textbf{Minimum-sample gate:} Requires at least 3 historical window samples before regression activates; otherwise it falls back purely to $\hat{\tau}_{\text{EA}}$.
\item \textbf{Trust-region clamp:} In log space, regression predictions are strictly clamped:
\begin{equation}
\ln \hat{\tau}_{\text{reg}} \in \left[ \ln \hat{\tau}_{\text{EA}} - \ln(5.0),\ \ln \hat{\tau}_{\text{EA}} + \ln(5.0) \right]
\end{equation}
ensuring the estimate remains strictly within $[0.2\times, 5.0\times]$ of the classical exponential baseline, precluding numerical overflow.
\end{enumerate}
This extension uses a multi-burst alternating CPU/I-O process model and is
evaluated on seven synthetic workload types spanning stable, feature-driven,
uncorrelated, phase-changing, and correlation-reversing burst behaviour.

\section{Experimental Methodology and Results}

\subsection{Setup}
We report results from the repository's default configuration: 25 processes
per workload, 3 training / 3 validation / 5 test workload instances per
category (65 paired test workloads total after including the three
test-only shifted categories), 600 Q-learning training episodes, and the full
five-model burst predictor comparison (linear, $k$-NN, CART, random forest,
SVR). This is a deliberately reduced-scale instance of the protocol specified
for this study -- intentionally so, as discussed in \S VI-C -- runnable
end-to-end in under 30 seconds; a \texttt{-{}-full} flag scales every sample
size and training budget up without changing the algorithms themselves.

Algorithm B reduced mean waiting time by $32\%$ relative to A, the strongest

read this as evidence that adaptive quantum selection is unhelpful in
general -- E's tuning grid and F's training budget are both deliberately
small here (\S VI-C) -- but we report it exactly as measured rather than
omitting or softening a negative result.

\section{Implementation and Reproducibility}

\subsection{Open-Source Simulator}
All six algorithms, five burst-prediction models, the Q-learning agent, and
CWABP are implemented in \texttt{schedsim}, a $\sim$1,700-line Python package
with no modification to any real kernel. The repository accompanying this
paper includes the exact code used to produce every table above.

\subsection{Verification and Property-Based Testing Suite}
Beyond classical empirical metrics, \texttt{schedsim} enforces structural invariants using two complementary testing layers:
\begin{enumerate}[leftmargin=*,itemsep=1pt,topsep=2pt]
\item \textbf{Unit and Invariant Regression Suite (40 tests):} Verifies structural identity claims: $B(\alpha{=}1) \equiv A$ and $C\text{-with-safeguards-disabled} \equiv B$, both checked pid-for-pid across the dispatch event log; $G{=}0 \Rightarrow$ no priority inversion outside explicit override events; absence of burst leakage in feature matrices; bounded Q-learning state indices $\in [0, 144)$; and analytical bounds for turnaround time ($T_i = W_i + b_i$), Jain's fairness index ($\in [1/n, 1]$), and starvation violation counts ($\in [0, n]$).
\item \textbf{Property-Based Randomized Testing (18 Hypothesis suites):} To guarantee that invariants hold universally across the unbounded combinatorial input space, property-based testing via the \texttt{Hypothesis} framework evaluates thousands of randomly generated workloads (randomized process count, burst distributions, arrival modes, and noise strengths). If an invariant is violated, Hypothesis automatically shrinks the counterexample to the minimal reproducing workload seed.
\end{enumerate}

\subsection{Continuous Training and Data-Flywheel Framework}
To investigate whether offline predictors and the tabular Q-agent continue to improve beyond fixed pilot batches, we designed an extensible continuous training suite (\texttt{train.py}):
\begin{itemize}[leftmargin=*,itemsep=1pt,topsep=2pt]
\item \textbf{Append-Only Training Pool (\texttt{schedsim/pool.py}):} Workloads randomly sampled from the combinatorial specification space append observed feature-burst tuples to an immutable dataset (\texttt{training\_pool.csv}). Seeds are drawn from $[3\times 10^6, 4\times 10^6)$, strictly disjoint from the evaluation splits.
\item \textbf{Model Checkpointing and Leaderboard (\texttt{schedsim/checkpoint.py}):} All five regression models are refit on the accumulated pool, logging validation RMSE and saving versioned checkpoints alongside an atomic \texttt{predictor\_latest.pkl}.
\item \textbf{Resumable Q-Learning:} Episode training warm-starts from the serialized Q-table (\texttt{qtable\_latest.npz}), decaying exploration $\varepsilon$ as a function of cumulative lifetime episodes.
\end{itemize}

\subsection{Two Bugs This Project's Own Testing Caught}
Development of this simulator surfaced two genuine correctness issues worth
reporting, since they illustrate why the open, tested implementation matters
beyond the protocol description alone. First, an early version of the CWABP
multi-burst generator precomputed each process's burst arrival times assuming
no queueing contention; under real contention this let a process's
\emph{own} next burst appear ready before its current one had actually been
simulated to completion, inflating mean waiting time by roughly $8\times$
before being caught and fixed by switching to online, completion-time-driven
burst generation. Second, a small-window spurious correlation in CWABP could
combine with an out-of-range feature value to overflow \texttt{math.exp}
during prediction; this was caught by an adversarial unit test
(\texttt{\seqsplit{test\_cwabp\_bounded\_even\_under\_spurious\_small\_window\_correlation}})
and fixed with the log-space trust-region clamp described in \S V. Both fixes
are reflected in the numbers reported here.

\subsection{Threats to Validity}
\textbf{Internal validity.} Validation workloads are used twice -- to select
burst-prediction hyperparameters and to select scheduler parameters -- which
can make validation-set estimates optimistic; the disjoint test split
reported throughout this paper is never touched during either tuning step.
The Round Robin quantum candidate set $\{2,4,8,16\}$ and the Q-learning state
bin boundaries (\S IV-D) are design choices, not exhaustively tuned.
\textbf{External validity.} All workloads are synthetic with a known,
designed feature-burst relationship; a single CPU is simulated with no
memory or cache effects, and the main study assumes one burst per process
with no I/O (CWABP relaxes this only for its own comparison, \S V).
Absolute numbers should not be read as transferable to a real kernel --
only the \emph{relative} comparisons between algorithms, and even these are
preliminary at pilot scale. \textbf{Statistical validity.} Workloads within a
category are similar by construction, so the reported Wilcoxon tests
describe this study's designed workload mixture specifically, not an
external population of real-world traffic; Holm correction is applied within
the six-comparison family reported in Table~\ref{tab:stats} but not across
every analysis in the paper as a whole. \textbf{Construct validity.} Waiting
and turnaround time under the single-burst model are simplifications of
scheduling behaviour in a real multiprogrammed system with blocking I/O.

\subsection{Limitations and Future Work}
Results here are pilot-scale: smaller sample sizes, a smaller Q-learning
training budget, and a coarser tuning grid than the protocol this study
specifies in full, run via \texttt{run\_experiment.py -{}-full} for a larger
instance of the identical pipeline. Planned next steps include: a full-scale
run with the complete sample sizes and training budget; validation against
real process traces rather than synthetic workloads; a kernel-level
prototype to measure real prediction overhead directly; deep Q-networks or
policy-gradient quantum selection once the tabular baseline is better
understood at full scale; and multi-core scheduling, which this study does
not address.

\section{Conclusion}
At pilot scale, ML-weighted priority scheduling (B) delivered a large,
statistically robust reduction in mean waiting time over the classical
baseline, and its fairness-protected variant (C) delivered a smaller but
still positive reduction while substantially improving worst-case waiting --
though not, in this configuration, the count of starvation-threshold
violations, a nuance the algorithm's own design explicitly does not rule
out. Neither adaptive Round Robin variant beat the simple fixed-quantum
baseline at this scale, a negative result reported without qualification.
CWABP matched or modestly improved on classical exponential averaging across
every tested condition, including adversarial ones, which we attribute to the
trust-region safeguard added after the project's own tests surfaced a
genuine failure mode. Future work includes the full-scale protocol run, real
workload traces, and a kernel-level prototype; see the repository for the
exact commands to extend any result here.
